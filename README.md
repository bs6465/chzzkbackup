# ChzzkBackup

Docker Compose 홈서버에서 실행하는 치지직/트윗캐스트 생방송 녹화 및 채팅 백업 대시보드입니다.

## 주요 기능

- 등록한 치지직 unique ID 또는 트윗캐스트 screen ID의 생방송 상태를 10초 주기로 감지합니다.
- 같은 방송의 연결 실패는 한 세션에 기록하고 최대 5분 지수 백오프로 자동 복구합니다. 방송 중 생긴 여러 녹화 조각은 종료 확인 후 하나의 영상으로 인코딩합니다.
- 방송 중에는 임시 `.ts.part` 파일로 녹화합니다.
- 방송 중에는 채팅도 `./temp`의 `.part` 파일로 저장한 뒤 세션 종료 시 최종 채팅 폴더로 이동합니다.
- 방송 종료 후 CPU `libx264`, `veryfast`, CRF 28 설정으로 압축된 `.mp4` 파일을 생성합니다.
- 인코딩 중인 작업의 진행률, 처리 시간, 속도, 예상 남은 시간을 대시보드에 표시합니다.
- 치지직은 `chzzk-python`, 트윗캐스트는 TwitCasting API v2 댓글 조회로 채팅을 수집하고 JSONL, CSV 파일을 함께 저장합니다. JSONL에는 원본 이벤트를 보존하고 CSV는 기본 표시 컬럼만 저장합니다.
- Tailscale 또는 홈서버 내부망 사용을 전제로 인증 없는 웹 대시보드를 제공합니다.
- 브라우저별 로컬 설정으로 라이트/다크 모드를 전환할 수 있습니다.
- 채널, 토큰, 녹화 세션, 인코딩 큐, 로그 상태를 SQLite에 저장합니다.
- 기존 MP4를 자동 색인하는 썸네일 보관함과 HTTP Range 재생·다운로드를 제공합니다.
- 채널별 보관일수·최대 영상 개수·최대 MP4 용량 정책과 영상별 상속·무기한·지정일 보호 예외를 관리합니다.
- 만료 영상은 7일 휴지통을 거쳐 삭제되며, 복원·즉시 삭제·삭제 이력 조회를 지원합니다.
- 플레이어에서 시작·끝 시각을 지정해 무인코딩 방식으로 구간 MP4를 생성하고 24시간 동안 다운로드할 수 있습니다.
- 플레이어에서 현재 영상 프레임을 원본 해상도 PNG로 저장할 수 있으며 `S` 키 단축키를 지원합니다.
- 플레이어의 채팅 사이드패널은 영상 시점과 자동 동기화되며 유형 필터, 검색, 클릭 탐색, 영상별 ±60초 딜레이 보정을 지원합니다. 채널 관리에서 새 녹화에 복사할 기본 보정값을 지정할 수 있습니다.
- 녹화 중 방송과 다시보기에서 메모가 있는 시점·구간 북마크를 여러 개 저장하고, 시작·끝 재설정과 영상별 전체 시간 보정·수정·삭제·클릭 재생을 지원합니다.
- 다시보기에서 `←/→`는 5초, `Shift+←/→`는 10초씩 이동하며 화면의 ±10초 버튼도 사용할 수 있습니다.
- 인코딩 실패는 원본을 보존하고 1분, 5분, 15분 간격으로 최대 3회 자동 재시도합니다.

## 경로

- 대시보드: `http://100.105.18.90:8733` (Tailscale 전용)
- 영상 보관함: `http://100.105.18.90:8733/library`
- 임시 녹화 파일: `./temp`
- 임시 구간 다운로드 파일: `./temp/clips` (완료 후 24시간 보관)
- 임시 채팅 파일: `./temp/*.chat.jsonl.part`, `./temp/*.chat.csv.part`
- 앱 DB 및 로그 상태: `./data`
- 최종 영상: `/home/bsubt/passport/chzzk_backup/<스트리머명>/`
- 트윗캐스트 최종 영상: `/home/bsubt/passport/chzzk_backup/트윗캐스트/<스트리머명>/`
- 채팅 파일: 각 최종 영상 폴더 아래 `채팅/`
- 저장 파일명 형식: `[YYMMDD HH-mm-ss] 스트리머명 - 제목.ext`
- 대시보드 로그 보관: 30일 이내, 동시에 최신 1000개까지만 유지

## 실행

```bash
docker compose build
docker compose up -d
```

Compose는 Tailscale 주소 `100.105.18.90:8733`에만 포트를 열고, 컨테이너를 UID/GID `1000:1000`으로 실행합니다. 헬스 엔드포인트는 `/health`입니다.

## 운영 방식

1. 대시보드에 접속합니다.
2. 치지직 계정의 `NID_SES`, `NID_AUT` 토큰을 저장합니다.
3. 트윗캐스트 채팅 수집이 필요하면 Read 권한이 있는 TwitCasting OAuth Access Token을 저장합니다.
4. 녹화할 치지직 unique ID 또는 트윗캐스트 screen ID를 등록합니다.
   - 트윗캐스트는 `screen_id`, `@screen_id`, `https://twitcasting.tv/screen_id` 형식을 받을 수 있습니다.
   - 트윗캐스트 비밀번호 방송은 지원하지 않습니다.
5. 등록된 채널이 생방송을 시작하면 자동으로 녹화와 채팅 저장을 시작합니다.
6. 방송 종료 후 인코딩 큐에서 `.mp4` 파일을 생성합니다.
7. 보관함에서 완료 영상을 검색·필터하고 채팅과 함께 재생합니다.
8. 운영 화면의 저장 정책에서 채널별 제한을 설정하고, 보관함 또는 플레이어에서 영상별 예외를 지정합니다.
9. 플레이어의 구간 다운로드에서 현재 재생 위치를 시작·끝으로 지정해 임시 MP4를 생성합니다.
10. 영상 아래 `스크린샷 저장 (S)` 버튼 또는 `S` 키로 현재 프레임을 PNG로 저장합니다.
11. 채널 행의 `싱크`에서 새 녹화의 기본값을 정하고, 플레이어의 `−0.5초`, `+0.5초`, `채널 기본` 버튼으로 현재 영상의 채팅·북마크 시차를 각각 보정합니다.
12. 녹화 중 또는 다시보기에서 `현재 시점 체크`/`현재 위치 북마크`로 시점 북마크를, `구간 시작`과 각 행의 끝 버튼으로 구간 북마크를 추가합니다. `B` 키는 시점 북마크를 추가합니다.
13. 다시보기 북마크의 시작·끝과 내용을 직접 수정하거나 현재 재생 위치로 바꾸고 시점·구간 종류를 서로 전환할 수 있습니다.

녹화 세션의 제목은 대시보드에서 수정할 수 있으며, 최종 영상과 채팅 파일명에도 같은 제목이 반영됩니다.

저장 정책은 처음에는 모든 채널이 무기한입니다. 기간·개수·용량 제한 중 하나라도 초과하면 오래된 상속 영상부터 휴지통으로 이동하며, 무기한 영상과 지정일까지 보호되는 영상은 제한 계산에서 제외됩니다. 휴지통은 같은 최종 저장 볼륨에 있으므로 7일 후 영구 삭제되거나 수동으로 비울 때 실제 디스크 공간이 확보됩니다.

구간 다운로드는 스트림 복사 방식이라 재인코딩보다 빠르지만, 키프레임 위치에 따라 요청한 시작·끝과 실제 결과가 수초 달라질 수 있습니다. 구간 작업은 한 번에 하나씩 실행되며 결과 생성 후에도 시스템 디스크에 100GiB의 여유 공간을 남길 수 있을 때만 요청을 받습니다.

앱은 시작 직후와 1시간마다 최종 저장 폴더를 증분 색인합니다. DB에 없던 기존 MP4도 파일명에서 채널, 제목, 시작 시각을 복원하며 10초 지점 썸네일을 생성합니다. 외부에서 사라진 파일은 이력을 삭제하지 않고 사용 불가 상태로 보존합니다.

스키마가 갱신될 때는 SQLite 마이그레이션 전에 `./data/backups`에 백업을 생성하고 최근 5개를 유지합니다. 기존 영상과 신규 채널의 초기 저장 정책은 모두 무기한입니다.

기존 채팅 CSV를 새 표준 컬럼으로 통일하려면 다음 명령을 사용합니다.

```bash
uv run python -m app.chat_csv_migrate /home/bsubt/passport/chzzk_backup
```

## Git 설정

이 프로젝트의 원격 저장소는 다음 SSH 주소를 사용합니다.

```bash
git@github.com:bs6465/chzzkbackup.git
```

서버에 GitHub SSH 키가 없다면 다음 명령으로 키를 생성한 뒤, 출력된 공개키를 GitHub에 등록합니다.

```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_chzzkbackup -C "chzzkbackup-home-server"
cat ~/.ssh/id_ed25519_chzzkbackup.pub
```
